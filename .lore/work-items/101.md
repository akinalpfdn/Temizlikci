Measured 2026-09-22 in the running Debug app (ps RSS every second) during a full "Macintosh HD" scan: ~2 min at ~378% CPU, peak RSS 1,112 MB at the moment the scan finished (01:09:46), dropping to ~49 MB while idle afterwards (likely memory compression). For comparison, ~/Documents/GitHub (561k files) peaked at 219 MB in the test host.

The peak coincides with the end of the scan, which suggests the final tree assembly plus the first layout/chain pass temporarily duplicate data.

Candidate fixes (measure each, keep what helps):
- Store the name only in `FileNode`; derive URL/id from the ancestor chain instead of a `URL` + path `String` per node.
- Avoid re-sorting/copying child arrays in `FileNode.directory`.
- Stop keeping `completedTopLevel` in progress snapshots after the scan ends.
- Profile with Instruments (Allocations) on a Release build before optimizing further.

Target to agree with the developer: below ~500 MB for this disk.
